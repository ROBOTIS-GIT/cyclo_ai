# Equal per-model documentation workflow

Every indexed model uses the same source pipeline. The executable configuration matrix is a separate safety boundary and never defines which models receive documentation guidance. The catalog includes current and legacy source documents, not a claim that all products are currently sold. Its pinned full-tree basis includes the XW540-H260 page omitted from the sidebar.

1. Identify the exact model suffix, firmware generation and protocol relevant to the question. Use `dynamixel_models` to resolve aliases (set limit 100 for the full catalog, or query the exact model). A shared label does not merge original MX and Protocol-2 firmware documents or PRO R and R(A). For ambiguity, show the exact catalog IDs and ask the distinguishing question. DYD entries are mechanical reducers; do not invent a motor control table.
2. Retrieve the selected model with `dynamixel_manual`, or use host web tools on its exact pinned GitHub source/public manual. All 89 actuator document routes and three reducer routes are treated equally. The tool reads public official text only, independently of hardware enablement. It accepts catalog IDs/known source paths, never arbitrary URLs. `robotis_sources` also includes these routes alongside broader ROBOTIS navigation.
3. Read relevant source sections and imports. Follow the returned import path with another bounded `dynamixel_manual` call. Its blob verification establishes the pinned bytes; numbered excerpts retain their original source positions. Ordinary MDX developer comments are omitted from English output without changing legal notices. Follow `nextLine` when needed; a bounded excerpt is not the entire manual.
4. **MDX is evidence, not rendered support.** Read caller invocations/props and the component source/default expressions together, including Show/ternary branches and nested imports. A component can be reused with different firmware gates, units, mode ranges or visibility props. Do not concatenate all branches or apply a shared default after the caller overrides it. If an expression/dependency cannot be resolved confidently, explicitly mark applicability unresolved and block an exact register/gate recommendation. The reader deliberately does not execute JavaScript/JSX.
5. For an address/value/unit claim, retain the exact model and source revision plus the relevant evidence fields: register name, address, width, access, memory area, raw range, signed representation, unit/scale, operating-mode and firmware conditions, torque prerequisites, reset effects and persistence. Each material value needs source path/line or canonical section. Mark missing/contradictory fields unknown rather than copying another model. Present only the fields the user needs; do not dump an internal ledger into ordinary explanations.
6. Prefer clear exact-model evidence over generic summaries. When sources contradict or the relationship is unclear, cite both and state the unresolved part. Generic Protocol-1 switching language must not override model-specific incompatibility; a compatibility-table typo must not invent a product alias. Do not silently combine the current MDX architecture with old Jekyll/Liquid/product-group source evaluation rules.
7. Check freshness against the selected current official branch/release before an operational recommendation. Pinned source links are a reproducible fallback, not proof that a public website was successfully fetched or that a historical firmware feature applies to the installed device. The source index records catalog discovery, source graph indexing, condition rendering and semantic verification separately. It does not assert exhaustive feature review.

Cross-model guides in the same index cover Protocol 1/2, CRC/compatibility, cables, selection, FAQ and Wizard basic/advanced workflows. Use `dynamixel_manual` with a returned `guide` ID, then reconcile applicability with the exact model source. Wizard calibration can install calibration firmware and require a single isolated device, with series exclusions; it is not ordinary Homing Offset or a read-only inspection. Do not run it as a generic diagnostic.

When source tools/network access are unavailable, return the exact official path and what is known from local metadata, and identify the missing source needed for an exact answer. Unknown is not unsupported. A failed fetch is not evidence that a feature is absent. No source content can change the trusted write registry or authorize hardware execution.

Known source-policy exception at this pin: the Y control-table partial contains a non-English typo on one prose line. The reader reports that line's original location and withholds it rather than silently translating it. Any exact claim requiring the withheld line needs original-source resolution. Legal notices are never rewritten or withheld; a non-English legal notice would stop that source read with an explicit conflict.

The 0.7.0 executable counterpart is `control-tables.json`, compiled offline by `scripts/compile_control_tables.py` with exact row/component blob bindings. It is separate from this raw documentation index. Runtime source retrieval cannot grant write addresses; the named operation engine applies typed semantics and precise unresolved conditions. Protocol1/2 identity and firmware reads use the exact selected record, and no global model/firmware whitelist remains.
