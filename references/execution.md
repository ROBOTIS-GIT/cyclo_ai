# Execution contract

This version combines AI Sapiens Skills with a separately gated local firmware MCP. It has no hooks, background scheduler, GPU service, robot registry or credential store. Installation does not provide training or robot-deployment execution access. Never claim an action happened without an observed result.

Hardware tools are available by default, but never run automatically. External jobs still require a real authorized executor. Set `CYCLO_OFFLINE=1` for device-free planning; legacy module enable flags set to `0` also disable that module. Product instructions do not authorize device access, GPU jobs, global installations, network exposure, credentials, robot changes, policy deployment or publication. Follow the actual task's authorized scope and preserve unrelated user services and settings.

For later user tasks, preserve the task's existing authorizations and restrictions. Read-only local inspection and reversible work inside the chosen project can proceed when in scope. Separate environment mutation/download/container startup, paid or long GPU execution, robot connection/file transfer, and live actuation. Obtain missing authorization at the concrete step, with the exact target and effect. Do not repeatedly ask for permissions already given.

Use a new isolated project path. Inspect existing files, git status and container names/mounts before changes. Never overwrite user work, switch a dirty checkout, edit global settings, replace a driver, run container clean, or reuse another service's ports/mounts as an incidental setup step. Review install scripts and Docker configuration before running them; bind mounts, privileged mode and shared hardware require the host's actual approval.

Before a long job: identify a real terminal/SSH/scheduler executor, available GPU and budget; record repository commit/submodules, container/image versions, command/arguments, cwd, input hashes, log path, start time, process/job/session ID, stop procedure and output directory in a task-local run record. Use the executor's real status mechanism. Report queued/running/completed/failed/unknown from evidence; checkpoint existence alone is not completion. If no persistent executor exists, deliver commands and mark execution pending. Never promise future monitoring from a skill installation. Check uncertain outcomes before retrying, and do not automatically restart failed costly jobs.

After failure: preserve logs/checkpoints and partial output, identify the failed stage and known effects, then make a scoped correction. Do not retry a denied operation without materially new relevant evidence. Document backup and rollback before replacing config/assets. Do not remove input data after conversion even if the manual says it may be removed.

A successful simulation or export does not establish hardware safety. For motor operation re-read the live operation, RC and Sim2Real guides for that robot/revision; require an onsite operator and separate authorization. Keep RC priority, feedback readiness, heartbeat timeouts and Damping behavior intact. Do not start robot services merely to diagnose file deployment.
