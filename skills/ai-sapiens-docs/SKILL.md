# Ai Sapiens Docs

Read [execution boundaries](../../references/execution.md) before commands or changes, and [official retrieval](../../references/sources.md) before factual guidance. Fetch only the relevant source and reference; do not load the whole manual. Preserve the user's instructions and authorization. This workflow has no GPU/robot executor or credential store; the separate firmware MCP cannot execute it.

1. Locate the topic in [coverage](../../references/coverage.md) or [index](../../references/manual-index.json). Use the source-retrieval process; metadata is a routing map, not an automatically refreshed corpus.
2. For hardware/electrical/software questions read [platform](references/platform.md); do not infer wiring or repair steps from a specification table. For other topics load the owning Skill only when its workflow applies, using the index path.
3. For an ambiguous request ask the smallest useful choice: explain a concept, prepare a procedure, or inspect a supplied error/artifact. “Control”, “learn” and “connect” can mean different physical operations. Preserve already selected backend/robot revision.
4. Answer with direct official citations and source dates/version limits, then distinguish packaged coverage from execution evidence. Coverage is not an overall support percentage. GMR, K1 LeRobot and Cyclo Intelligence are Coming Soon at the baseline; verify current status before future use. Do not silently substitute AI Worker/OMY procedures for K1.
5. For source outages provide the dated baseline and exact unresolved question; do not invent a document service or assert current facts. Explain that a later user-approved executor is needed for operations. No default installation, persistent connection or publication is part of a documentation answer.

Examples: “Find the AI Sapiens electrical specifications in the manual”; “Is GMR training available now?”; “Should I start with walking or video Mimic?”
